# Module List Catchup Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add `bedrock`, `cognito`, `dynamodb`, and `ssm` to the per-module envelope schema enum and the `scope-schema-validate.sh` hook so envelopes from those four enum scripts validate successfully.

**Architecture:** Two artifacts hardcode the module name list — `config/schemas/module-envelope.schema.json` (the schema's `module.enum` array) and `config/hooks/scope-schema-validate.sh` (a `case` match against filename basenames and a second `case` validating the `module` field value). Both need to grow by four entries. Add Node-based tests that consume both artifacts directly so future module additions get caught.

**Tech Stack:** Plain Node test runner (no test framework), bash hook with `jq`, JSON Schema (consumed by hook only — no validator dependency).

**Background — why this exists:** SCOPE's 16 enum scripts each write a per-module envelope JSON file (`$RUN_DIR/<module>.json`). The schema and hook were last updated when only 12 modules existed; `bedrock.js`, `cognito.js`, `dynamodb.js`, and `ssm.js` were added later without updating the enum lists. The hook currently never fires on agent runs (subagents write via `bash` redirect, not `Write`), so the bug hasn't been exposed in production — but the schema is also referenced by CI tooling and any future Write-tool-based writer, so the inconsistency needs fixing before Phase B coverage work lands on top of it.

**Important context:**
- The installed copy at `.claude/hooks/scope-schema-validate.sh` is generated by `node bin/install.js` and is gitignored (`.gitignore:12`). Do **not** edit it directly. Edit only `config/hooks/scope-schema-validate.sh` (the source of truth). Operators re-run `node bin/install.js` to refresh their installed hook.
- Tests must invoke `config/hooks/scope-schema-validate.sh` directly (not the installed copy) so they pass in any environment regardless of install state.
- Project uses a custom Node test runner: every `*.test.js` file in `test/` is executed via `node test/run-all.js`. No mocha/jest. Existing test style: `assert` from `node:assert`, `test()` wrapper that increments `passed`/`failed` counters, exit code reflects failures. Match this style.

## Task 3: Hook acceptance test for new modules (failing first)

**Files:**
- Create: `test/hook-schema-validate.test.js`

**Test design — read this before writing:** "Acceptance" for this hook is empty stdout (silent pass). A file that the hook *doesn't recognize* (filename basename doesn't match the `case` block) also produces empty stdout — it falls through to the default arm and exits 0. So a test that writes a valid envelope and expects empty stdout passes whether the hook recognizes the file or not. Useless as a regression check.

To prove the hook actually *handles* `bedrock.json` / `cognito.json` / `dynamodb.json` / `ssm.json`, send a **deliberately invalid** envelope and assert the hook blocks it. If the case block doesn't match, the file falls through and the bad envelope is silently accepted — that's the bug we're catching.

- [ ] **Step 1: Write the failing test**

Create `test/hook-schema-validate.test.js` with this exact content:

```js
'use strict';

const assert = require('node:assert');
const { spawnSync } = require('node:child_process');
const fs = require('node:fs');
const os = require('node:os');
const path = require('node:path');

const HOOK = path.join(__dirname, '..', 'config', 'hooks', 'scope-schema-validate.sh');

let passed = 0;
let failed = 0;

function test(name, fn) {
  try {
    fn();
    console.log(`  PASS: ${name}`);
    passed++;
  } catch (err) {
    console.error(`  FAIL: ${name}`);
    console.error(`    ${err.message}`);
    failed++;
  }
}

// Runs the hook with a synthetic PostToolUse payload pointing at a temp file
// we just wrote. Returns { stdout, stderr, code }.
function runHook(envelopeBody, filename) {
  const tmpDir = fs.mkdtempSync(path.join(os.tmpdir(), 'scope-hook-test-'));
  try {
    const filePath = path.join(tmpDir, filename);
    fs.writeFileSync(filePath, JSON.stringify(envelopeBody, null, 2));
    const hookInput = JSON.stringify({
      tool_name: 'Write',
      tool_input: { file_path: filePath },
    });
    const result = spawnSync('bash', [HOOK], { input: hookInput, encoding: 'utf-8' });
    return { stdout: result.stdout, stderr: result.stderr, code: result.status };
  } finally {
    fs.rmSync(tmpDir, { recursive: true, force: true });
  }
}

function validEnvelope(moduleName) {
  return {
    module: moduleName,
    account_id: '123456789012',
    region: 'us-east-1',
    timestamp: '2026-05-17T12:00:00Z',
    status: 'complete',
    findings: [],
  };
}

function assertAccepted(out, label) {
  if (!out.stdout || out.stdout.trim() === '') return; // empty stdout = accepted
  let parsed;
  try { parsed = JSON.parse(out.stdout); } catch { return; } // non-JSON stdout = not a block decision
  assert.notStrictEqual(
    parsed.decision,
    'block',
    `hook blocked ${label}: ${parsed.reason || '(no reason)'}`
  );
}

function assertBlocked(out, label) {
  assert.ok(out.stdout && out.stdout.trim() !== '', `expected stdout for blocked ${label}, got empty`);
  let parsed;
  try { parsed = JSON.parse(out.stdout); } catch (e) {
    throw new Error(`expected JSON decision for blocked ${label}, got non-JSON: ${out.stdout}`);
  }
  assert.strictEqual(parsed.decision, 'block', `expected decision:block for ${label}, got: ${parsed.decision}`);
}

// --- New-module recognition: send a deliberately invalid envelope for each
// new module. If the hook recognizes the filename, it validates the envelope,
// sees missing required `findings`, and emits a block decision. If the hook
// doesn't recognize the filename, the file falls through to the default arm
// and the bad envelope is silently accepted — that's the bug.
for (const mod of ['bedrock', 'cognito', 'dynamodb', 'ssm']) {
  test(`hook recognizes ${mod}.json and validates its envelope`, () => {
    const env = validEnvelope(mod);
    delete env.findings; // make it invalid
    const out = runHook(env, `${mod}.json`);
    assertBlocked(out, `${mod} (missing findings)`);
  });
}

// --- Regression guards: existing behavior must still work.

test('hook accepts a valid iam envelope', () => {
  const out = runHook(validEnvelope('iam'), 'iam.json');
  assertAccepted(out, 'iam');
});

test('hook blocks an iam envelope with an unknown module field value', () => {
  const env = validEnvelope('iam');
  env.module = 'invalidmod';
  const out = runHook(env, 'iam.json'); // filename routes to module-envelope path
  assertBlocked(out, 'invalidmod');
});

console.log(`\n${passed} passed, ${failed} failed`);
process.exit(failed > 0 ? 1 : 0);
```
